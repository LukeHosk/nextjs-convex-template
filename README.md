# nextjs-convex-template

A full-stack starter template built with Next.js, Convex, and shadcn/ui. Includes authentication, file storage, E2E testing, and CI/CD out of the box.

## Stack

| Layer          | Technology                                                        |
| -------------- | ----------------------------------------------------------------- |
| Frontend       | Next.js 16 (App Router), React 19, TypeScript                     |
| Backend        | [Convex](https://convex.dev) — serverless database + functions    |
| Auth           | [@convex-dev/auth](https://labs.convex.dev/auth) — email/password |
| UI             | [shadcn/ui](https://ui.shadcn.com) (Base Nova), Tailwind CSS v4   |
| Storage        | Convex native file storage                                        |
| Testing        | Playwright (E2E)                                                  |
| CI/CD          | GitHub Actions — code review + preview seeding                    |
| Env validation | [@t3-oss/env-nextjs](https://env.t3.gg) + Zod                     |

The demo app is a simple authenticated todo list — a minimal but real example of Convex queries, mutations, and real-time reactivity.

## Quick start

**Prerequisites:** Node.js 20+, pnpm, a [Convex account](https://dashboard.convex.dev)

```bash
# 1. Clone and install
git clone https://github.com/lukehoskins/nextjs-convex-template
cd nextjs-convex-template
pnpm install

# 2. Initialise the template
pnpm run init-template

# 3. Set up environment
cp .env.example .env.local
# Fill in CONVEX_DEPLOYMENT, NEXT_PUBLIC_CONVEX_URL, NEXT_PUBLIC_CONVEX_SITE_URL
# (these are printed after `npx convex dev` initialises your project)

# 4. Start dev server (runs Next.js + Convex backend together)
pnpm dev
```

`pnpm run init-template` prompts for a project name, updates the starter branding in `package.json`, `app/layout.tsx`, `app/page.tsx`, and this README, and can launch `pnpm dev` for you to complete the initial Convex setup.

On first run, `predev` will initialise the Convex project and run `setup.mjs` to configure the auth provider domain automatically.

Open [http://localhost:3000](http://localhost:3000) and sign up with any email/password.

## Environment variables

See `.env.example` for the full list. Key variables:

| Variable                        | Where to get it                                              |
| ------------------------------- | ------------------------------------------------------------ |
| `CONVEX_DEPLOYMENT`             | `npx convex dev` output                                      |
| `NEXT_PUBLIC_CONVEX_URL`        | Convex dashboard → project settings                          |
| `NEXT_PUBLIC_CONVEX_SITE_URL`   | Convex dashboard → project settings                          |
| `SEED_SECRET`                   | Any random string — used to protect the `/api/seed` endpoint |
| `SEED_USER_EMAIL` / `_PASSWORD` | Credentials for the test user created by `pnpm seed:all`     |

## Authentication

Email/password auth via `@convex-dev/auth`. The middleware in `proxy.ts` gates all routes except `/signin`. To add OAuth providers (GitHub, Google, etc.), see the [Convex Auth docs](https://labs.convex.dev/auth/config/oauth).

## File storage

`convex/storage.ts` provides generic upload/retrieval/delete helpers backed by Convex native storage. The `uploadedImages` table tracks metadata.

Alternative storage backends can be added later without changing the app structure.

## Seed data

```bash
pnpm seed:all   # creates two test users + sample todos
pnpm seed:user  # creates test users only
```

For CI/preview deployments, the `seed-preview` GitHub Actions workflow hits `/api/seed` automatically after each successful Vercel deployment.

## E2E tests

```bash
pnpm test:e2e        # run all Playwright tests
pnpm test:e2e:ui     # open Playwright UI
```

Tests live in `tests/e2e/`. `auth.setup.ts` signs in once and saves the session so auth state is reused across tests.

Requires the app to be running (`pnpm dev`) or set `PLAYWRIGHT_BASE_URL` to a deployed URL.

## Project structure

```
app/              Next.js App Router pages
  signin/         Public sign-in / sign-up page
  api/seed/       Seed endpoint (CI use)
components/       React components
  ui/             shadcn/ui components
convex/           Convex backend
  schema.ts       Database schema
  todos.ts        Todo CRUD functions
  storage.ts      File upload/retrieval helpers
  auth.ts         Auth provider config
  seed.ts         Seed actions
env/              Type-safe env schemas (@t3-oss/env-nextjs)
tests/e2e/        Playwright tests
```

## Type checking

`tsc --noEmit` requires Convex's generated types to exist. Run `npx convex dev --until-success` once before running the type checker. The `convex/_generated/` directory is gitignored (auto-generated by Convex).

## Replacing the sample app

The todo list is intentionally minimal. To start your own app:

1. Replace `convex/schema.ts` with your domain tables
2. Add your Convex query/mutation files alongside `convex/todos.ts`
3. Update `app/page.tsx` with your UI
4. Update `convex/seed.ts` to seed domain-appropriate data
5. Update `app/layout.tsx` metadata (title, description)
